# CT-e e NFS-e na integração fiscal existente

Overlay de código para a integração fiscal existente. NF-e, CT-e e NFS-e nacional têm rodadas todos os dias às **09h, 15h e 20h de Brasília**. Mantém a lista NOTAS_FISCAIS_SEFAZ, receptor autenticado, cursores separados e fila sequencial de WhatsApp. O corte operacional configurado é **01/09/2026**, pela emissão original, sem reiniciar NSUs, filas ou deduplicação. Não contém A1, chave privada, senha, token, XML/PDF real, fontes Windows, evidências privadas ou dados das filas.

NFS-e gera DANFSe nacional v2.0, modelo NT 008, no Windows por `%LOCALAPPDATA%\Energetica\Runtime\FiscalPdf\Scripts\python.exe`, com danfe_renderer.py, fiscal_document.py e national_danfse.py. As dependências fixadas em config/danfe-requirements.txt não contêm credenciais. Arial/Arial Bold e Microsoft Sans Serif são as fontes do próprio Windows; não são exportadas nem enviadas ao servidor. Não há dependência da API de PDF do ADN. NF-e e CT-e modelo 57 versão 4.00 continuam no Python pelo SSH existente. Leiautes sem suporte ficam pendentes, sem relatório XML alternativo.

Aplicar os arquivos à raiz existente preservando configurações e dados. O instalador prepara16arquivos, valida pré-requisitos/hashes e preserva cursores; validação não equivale a promoção nem a correção dos anexos. O PC deve permanecer ligado, conectado e com a sessão do usuário Windows ativa e o A1 disponível. Android, iOS e Windows exibem os anexos da mesma base; a coleta continua no Windows. O utilitário de instalação do Python é local e não faz parte deste overlay.

Testes Node são independentes do cwd e do tenant: node --test backend-patches/notas-fiscais-cte-nfse/tests/*.test.mjs. A fixture cria uma configuração fictícia temporária. Testes PowerShell e Python são executados no contexto da integração; não são comandos de captura. Leia os documentos nesta pasta para contratos de cada fonte, PDF e agendamento. A disponibilidade de NFS-e no ADN não comprova cobertura de todos os municípios.
