# Câmeras no Energético

O aplicativo lista os canais disponíveis para o usuário autenticado e pode abrir até oito câmeras na mesma grade. A API consulta o Microsoft Graph com a sessão do Energético e confere o ID da conta contra a lista de visualizadores. O limite de oito transmissões sob demanda é compartilhado entre os usuários. A abertura de cada transmissão pode aguardar até 75 segundos pelo vídeo. Cada sessão de vídeo vence em 20 minutos ou é encerrada após 12 segundos sem pedidos. Valide a reprodução simultânea com as fontes reais ao mudar os limites da unidade systemd.

Instale `gateway.py`, o adaptador da fonte e seus runtimes em `/opt/energetico-cameras`. A unidade systemd lê o arquivo privado `/etc/energetico-cameras/cameras.json` por meio de `LoadCredential`. O proxy HTTPS deve enviar somente `/api/portal-cameras` e `/api/portal-camera-media/*` para `127.0.0.1:8872`. Se configurar um tempo limite para a resposta de `/api/portal-cameras`, permita pelo menos 100 segundos para cobrir a autenticação e a abertura do vídeo. Remova o caminho de mídia dos logs de acesso do proxy, pois ele contém uma chave temporária de reprodução.

O JSON tem os campos `viewers` (IDs dos usuários no diretório), `origins` (origens HTTPS e Capacitor autorizadas), `ffmpeg` (caminho absoluto, com libx264), e `channels`. Cada canal define `id`, `label`, `format` (`hevc`, `h264` ou `mpegts`), `command` (lista de argumentos com executável absoluto), e opcionalmente `input` (JSON recebido pelo processo via stdin). A fonte escreve somente o fluxo de vídeo no stdout. As credenciais ficam no arquivo privado.

O adaptador iCSee utiliza a interface do cliente `xmplayer` instalado separadamente. Configure `PYTHONPATH` para apontar para essa instalação e para suas dependências, com Python 3.11 ou superior para o adaptador. O diretório do cliente precisa conter `desktop_monitor.json` e o diretório `screenshots` criado previamente. O campo `input` inclui `cloudId`, `username`, `password`, `channel` (índice a partir de zero), e `tlsPins` (`status` e `relay`, SHA-256 dos certificados aprovados). Se o fornecedor trocar um desses certificados, valide o novo certificado antes de atualizar o pin. Uma fonte compatível com o mesmo contrato pode ser usada para outros fabricantes.

O adaptador iCSee aceita comandos curtos de movimento somente durante uma sessão ao vivo. O histórico é consultado por data e, opcionalmente, por hora no armazenamento da própria câmera; cada item recebe uma identificação temporária vinculada ao usuário e ao canal, e o caminho original não é enviado ao aplicativo. A busca de um dia inteiro mostra até 512 trechos; o filtro de hora permite consultar períodos adicionais. A capacidade de movimento e a existência de gravações dependem de cada dispositivo.

## Fonte Yoosee

A fonte Yoosee abre vídeo ao vivo pela nuvem e entrega HEVC ao gateway, que gera o mesmo HLS em H.264 usado pelas outras câmeras. Cada canal aponta para `/usr/bin/python3`, `/opt/energetico-cameras/yoosee/yoosee_source.py` e `/opt/energetico-cameras/yoosee`, com formato `hevc` e `input.deviceId` numérico. O adaptador atual oferece vídeo ao vivo.

Compile `yoosee_live.cpp` com MSVC x64 e `/MD`, usando o cabeçalho e a biblioteca de importação do mesmo pacote do [GWTimes IoTVideo-PC](https://github.com/GWTimes/IoTVideo-PC). Instale o executável e as DLLs correspondentes em `yoosee/bin`. Instale o Wine x64 e os arquivos de idioma e dependências MinGW em `yoosee/runtime`, preservando a estrutura `usr` dos pacotes. Instale também o módulo de autenticação `yoosee_cloud` com seu arquivo de chaves e sua licença no diretório `yoosee`.

Instale e habilite a unidade `energetico-yoosee.service`. Forneça o JSON `yoosee.json` contendo `account`, `password` e os IDs numéricos das câmeras em `devices` em `/etc/energetico-cameras`, com acesso restrito a root. O serviço reutiliza a autenticação e mantém o fluxo comprimido de cada câmera em um processo do SDK com um prefixo Wine próprio. O gateway recebe o vídeo pelo socket Unix privado e só inicia a conversão HLS quando solicitado. O systemd fornece a credencial apenas à fonte. Valide o primeiro segmento e o avanço da sequência HLS de cada canal. Para cadastrar mais de uma câmera, valide também a reprodução simultânea.

Execute `python -B -m unittest discover -s automations/cameras -v` para testar a autorização e as rotas.
