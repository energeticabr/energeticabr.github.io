# Fonte nativa V380 no Energético

`v380_source.py` fala diretamente com o protocolo de vídeo V380 na porta TCP
8800. Não exige habilitar ONVIF/RTSP no firmware, instalar o aplicativo V380
no servidor nem redistribuir um SDK binário. A saída é vídeo Annex-B, enviado
ao mesmo gateway HLS e às mesmas regras de acesso Microsoft já existentes.
O catálogo e o limite de transmissões simultâneas continuam no gateway.

## O que foi verificado

- Peer TCP local independente valida os dois layouts de login (LAN e relay),
  credenciais AES, respostas divididas em várias leituras e início do vídeo.
- Frames sem criptografia e com a criptografia v31+, versão de comunicação
  21, fragmentação, ordenação, tamanho máximo e recusas de login.
- O adaptador executa como processo real, alimenta o FFmpeg do gateway,
  produz playlist/segmentos HLS e um segmento é decodificado pelo FFmpeg.
- O catálogo não entrega credenciais e o stderr não imprime a configuração.

Esses testes usam somente loopback e dados fictícios. Não comprovam a
compatibilidade de todos os firmwares, o acesso ao relay real nem a imagem de
uma câmera do usuário. O cliente foi implementado a partir dos campos de
protocolo documentados pelo projeto independente
[`PyanSofyan/V380Decoder`](https://github.com/PyanSofyan/V380Decoder/tree/0eb97f36d190bf3ecde26582b5e21bdc19c7122f),
em particular `V380Client.cs` e `DispatchRelayServer.cs`. Firmware com outro
formato de autenticação ou mídia falha com diagnóstico e precisa de validação.
PTZ, gravações do cartão e resgate de convites de compartilhamento não fazem
parte desta fonte de vídeo.

## Instalação no servidor existente

1. Instale as dependências no diretório já permitido pelo serviço:

   ```sh
   sudo python3 -m pip install --target /opt/energetico-cameras/deps \
     -r automations/cameras/requirements-v380.txt
   sudo install -m 0644 automations/cameras/v380_source.py \
     /opt/energetico-cameras/v380_source.py
   ```

2. Acrescente um canal ao array `channels` do arquivo privado
   `/etc/energetico-cameras/cameras.json`, preservando os canais existentes,
   `viewers`, `origins` e `ffmpeg`. Exemplo fictício para LAN/VPN:

   ```json
   {
     "id": "v380-obra",
     "label": "Obra · V380",
     "format": "h264",
     "command": ["/usr/bin/python3", "/opt/energetico-cameras/v380_source.py"],
     "input": {
       "deviceId": 12345678,
       "username": "admin",
       "password": "SUBSTITUIR_PELA_SENHA_DO_DISPOSITIVO",
       "mode": "lan",
       "host": "192.168.1.100",
       "port": 8800,
       "quality": "sd"
     }
   }
   ```

   A senha é a credencial permanente do dispositivo, não o PIN temporário
   de um QR de compartilhamento nem necessariamente a senha da conta V380.
   Nunca coloque o arquivo privado, QR, PIN ou senha no Git. Mantenha a
   configuração acessível somente ao administrador, com permissão `0600`.
   O gateway entrega as credenciais pelo stdin; nenhum segredo vai em argv.
   O campo `format` pertence ao gateway: use `hevc` se a fonte emitir H.265.
   `quality` aceita `sd` (padrão) ou `hd`.

3. Execute os testes e reinicie apenas o serviço existente:

   ```sh
   python3 -B -m unittest discover -s automations/cameras -v
   sudo systemctl restart energetico-cameras
   sudo systemctl is-active energetico-cameras
   ```

4. Abra **Câmeras** no Energético com uma conta já autorizada e selecione o
   canal. Só considere a câmera integrada após confirmar a imagem real.
   Essa mudança é no servidor; não precisa gerar novos binários iOS/Android.

## Acesso fora da rede

Há dois caminhos configuráveis:

- **VPN até a câmera:** mantenha `mode: "lan"` e use um IP alcançável pelo
  servidor. O IP privado da câmera só funciona se o servidor tiver rota até ele.
- **Relay V380:** use `mode: "cloud"`. Um `host` público configurado pelo
  administrador conecta diretamente ao relay aprovado. Sem `host`, a fonte
  envia o ID e uma assinatura de descoberta para
  `https://dispa1.av380.net:8001/api/v1/get_stream_server` e aceita somente IPs
  públicos na resposta. Não envia a senha nesse pedido e não segue redirects.

A descoberta remota deve ser executada somente após autorização do dono da
câmera para enviar os metadados ao serviço V380. Não existe downgrade
automático de HTTPS. Algumas instalações legadas usam somente HTTP; o campo
explícito `allowLegacyDiscovery: true` seleciona esse transporte e deve ser
habilitado apenas após aprovar esse destino e o envio de metadados sem TLS.
Uma vez escolhido o relay, o login nativo V380 usa TCP e o esquema próprio de
AES esperado pelo firmware; isso não equivale à proteção TLS ponta a ponta.
Prefira a LAN por VPN quando quiser manter esse tráfego em uma rede privada.

## Diagnóstico

O processo encerra sem repetir tentativas de senha quando a câmera recusa o
login. Problemas de socket, versão de firmware e configuração encerram a
fonte; o gateway mantém seu comportamento de indisponibilidade (`503`). Não
adicione um canal como funcional antes de testar credenciais e imagem reais.
O serviço descarta stderr das fontes em operação; para diagnóstico, execute o
adaptador sob o mesmo Python/PYTHONPATH, com a configuração privada no stdin.
Não cole credenciais na linha de comando, no histórico ou em logs públicos.
